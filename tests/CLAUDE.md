# tests/ Reference

The Catch2 test suite. Loaded when working on files in `tests/`. Run it with
`.\tools\run_tests.ps1 -Build` (the `/run-tests` skill). The raw build command
is in the root `CLAUDE.md`, and console-driving instructions are in
`TESTING.md`.

## File details

| File | Purpose |
|---|---|
| `catch.hpp` | Catch2 v2 single-header test framework (no external dependency) |
| `helpers.h` | `setupBoard()`, `clearBoard()`, `runGame()` -- shared test utilities; `fileExists()`; the `TestScratchSlot` registry of named, collision-free model-slot constants for tests needing a throwaway model file (see `ML_RESERVED_SLOTS`, `src/ml_eval.h`) |
| `test_main.cpp` | Catch2 entry point (defines `CATCH_CONFIG_MAIN`) |
| `test_move_validation.cpp` | Unit tests for `tryMoveWhite/Black` and `tryMoveQuickWhite/Black` |
| `test_win_detection.cpp` | Unit tests for `canWinWhite/Black` and `findWinWhite/Black` |
| `test_eval.cpp` | Unit tests for `evaluateBoard`, the Classic/Experimental equivalence check, and the incremental-eval walk asserting `g_evalPos` matches `evalPosFull` over make/unmake |
| `test_ai_integration.cpp` | MiniMax forced-win scenarios on hand-crafted positions. Search-value invariance under tt/ord (with and without quiescence), each carrying anti-vacuity node-count guards, added because both tests previously ran from a row-6 position where `canWinWhite()` collapsed the search to 17 nodes and neither flag could change anything. TT searcher-context regression (a prior search by the other player must not change what this one computes). Quiescence horizon-fix value test (a defended-capture exchange resolves to equal material at depth 1 + qs) |
| `test_game_outcomes.cpp` | Full-game outcome tests using puzzle boards (Black/White MiniMax vs TieredRandom) |
| `test_ml.cpp` | ML unit tests: feature determinism, `LinearModel` forward/save/load + SGD loss drop, `mlValueScore` bounds, Greedy winning move, LearnedPolicy legal move, Elo monotonicity, and the fast learned leaf tail being BIT-EXACT against the `std::tanh` reference (`mlSquashToEvalFast` vs `mlSquashToEvalReference` over a dense -30..+30 sweep at 1e-4 steps x 5 scales, the edge and extreme cases, and 400k pseudo-random inputs). Exactness is the requirement because a differing int would re-identify every `learned(...)@1` agent. The replication-study switches (`src/ml_tdleaf.h`): the closed forms (`tdTerminalTarget`, `tdScoreToProb` inverting the learned leaf tail on real positions, `tdOneSidedGrad`, the ordinal distribution against 200k draws, `e = 1` consuming no `rand()`), `mlv2MirrorFeatures` against a mirrored board, `ttPeek`/`ttGeneration`, and short `trainTDLeaf` runs showing that at `lr = 0` no switch changes what the search plays (nodes, plies, searches and results equal to the baseline, so the table walk and the take-back leave the search untouched), that each switch does change what is learned, that TreeStrap restricted to the root (`treeMinDepth` 99) reproduces rootstrap, that ordinal at `e = 0` plays other moves, and the provenance tokens and bad-value refusals |
| `test_gumbel.cpp` | Gumbel MCTS (`src/ai_gumbel.cpp`): the pure core math, plus the search telemetry contract -- after a `gumbelSearch` the four globals are populated (`g_lastNodes > 1`, the exact gate `src/ranking.cpp`'s `playOneGame` uses to credit a move's node count, `g_lastLeafs <= g_lastNodes`, `g_lastEffDepth >= 1.0`, `g_lastBudgetKind == BUDGET_SIMS`) and the node count rises with the simulation budget (32 versus 512) |
| `test_determinism.cpp` | Whether a deterministic agent's reply is a function of the POSITION or of how the opponent reached it. `pairGameTarget` caps a deterministic pair at 2 games on the premise that it is, and every book-wearing or `.opener(...)` agent breaks the symmetry by not searching for part of the game. A reference game is replayed under three perturbations, compared per ply by `positionKey` hash: White never searches and replays its recorded move, White is silent only for its first 8 plies (the `.opener(rand,moves=8)` shape), and both sides search normally but on a transposition table another game already dirtied. All three must reproduce exactly. Two positive controls make the passes falsifiable: the harness replaying its own reference identically, and a `.dil(prob=20)@1` opponent that MUST diverge (it does, at ply 1). Without that second control every "no divergence" would be unfalsifiable. The property holds because `setTTContext` salts the key with root side and evaluator, making a foreign entry a miss rather than a false hit, and because the ROOT move loop is unordered, so table-driven ordering cannot reorder the candidates a tie is broken among. A root-ordering change would need this test rerun. `time=` agents are deliberately not asserted: their depth depends on the wall clock, which is why `rankAgentIsDeterministic` already classifies them as stochastic |
| `test_train_budget.cpp` | The shared training-compute meter (`src/train_budget.h`) and the checkpoint-provenance contract. Pure-mechanism cases: wall-mark parsing (sorts, dedupes, rejects junk and non-positive marks), rung-path naming after the NOMINAL mark, the spend stamp round-tripping through a provenance line, an unstamped line reporting no spend rather than zero spend, the key lookup not matching inside a longer key (`opengames=`), a resumed ladder skipping marks the prior spend passed, marks coming due in order and consumed once each, and no configured stop meaning no stop. Integration cases run real short `trainTDLeaf` runs: two ladder rungs carrying their OWN `games=` counts and differing from each other (the exact pre-fix defect, where every rung claimed `cfg.games`), a wall-clock stop holding and still writing its rung, `--resume` continuing a cumulative count rather than restarting, and `--resume` refusing an unstamped checkpoint. The CPU-seconds meter charges busy work and not a sleeping wait |
| `test_ranking.cpp` | Ranking unit tests: ID canonical round trips + rejection battery (incl. stale/missing `@N` module versions, and legacy label spellings being reported with their modern form rather than accepted), the weight-subset rules (an omitted weight taking its registry default, a non-default zero surviving, the turn weight elided without `qs`/`part` but carried with it, and a chip-only Classic rescaling to `chip=100`), `rankDisplayId` dropping only CURRENT module versions and returning unparseable input verbatim, learned-model hash checks, codec completeness vs `g_evaluators`, roster parsing, a tripwire that no live roster agent's model slot falls in the reserved scratch range or on a general-range slot the suite itself still writes to (text-scans `ranking/roster.txt` rather than fully loading it, so it isn't blocked by an unrelated content-hash defect elsewhere in the store -- see `ML_RESERVED_SLOTS`, `src/ml_eval.h`, and the `TestScratchSlot` registry in `tests/helpers.h`), match-row round trip (new cpu/pc/ed fields + old-row sentinels) + board filter, regime classification off the canonical id (incl. a loadout not changing it, and the legacy learned() form reporting no regime rather than guessing), matchup residual reading ~0 when Elo explains the results, regime-balanced fit moving an over-represented bloc's ratings while reproducing the plain fit exactly when regimes are equal-sized, match-store sharding (shard-path naming incl. not colliding with `run_rank.ps1`'s per-worker temps, sealed shards loading ahead of the live tail, a gap ending the chain, sealing preserving every row while bounding part size, re-sealing being a no-op, appends still landing in the tail), the part index (a dropped line dropping those games from the fit, a listed-but-missing part being skipped not fatal), store splitting by roster membership (dry run writes nothing, the tagged bucket winning over `retired_other`, and the parts still loading as the original row set), scheduler color balance / incremental top-up / determinism, `--common-openings` giving every cohort agent the same couple seeds against a panel agent (and a `rand` opener seed playing one opening line whoever the agents are), BT fit accuracy + anchoring + disconnected components, gauntlet 1-D fit, pairgen (dilution schedule values, byte-identical determinism, zero-override equivalence, winner-filter tally honesty, open-plies divergence, asymmetric open-side divergence + default byte-identical back-compat + meta field, branch-mode determinism), opener-bias runs deterministically, identity-level `.opener(rand,N)@1` randomizes independent of pairgen's own opener flags + rejects unknown/argless opener kinds, opener-swap classifies deterministically, `agree` self-agreement being EXACTLY 1.0 (an agent polled against itself must repeat its own move, so anything less means the snapshot/rewind leaks board counters, `g_evalPos`, `g_mlAcc` or a stale TT entry and every agreement number would be measuring that leak) plus its anti-vacuity and argument-validation cases, and `rankCategoryOf` giving `cal=` precedence over `nodes=` so a calibrated wall-clock agent stays on the time track instead of silently merging into the node track |
