# Gumbel-Zero: mlp/conv architecture sweep -- Results

Plan: `gumbel-mcts-arch-plan-6-silver-thistle.md`. Head throughout:
`ab(deep=6,tt,ord,nodes=200k)@1` for pool agents; cohort agents are
`gaz(sims=N,cvisit=C,cscale=S,m=M)@1.learned(...)@1`. Fit date for every Elo
number below: 2026-08-22, `ranking/standings_screen_gzarch_pinned.tsv`
(pinned fit, screening pool frozen at `ranking/standings.tsv`, cohort agents
resolved only through pool games -- see `Docs/ranking-workflow.md`, "Default
gauntlet pool").

## What ran

92 draws (2 REF + 90 random, seed 8917, 45 mlp + 45 conv) x 4 checkpoint
rungs (100/400/1500/4000 games) = 368 checkpoints. Every checkpoint
gauntlet-rated at 16 games/opponent against the 27-agent
`ranking/roster_screening_pool.txt` (no cohort-internal games).

**Per-checkpoint data**: `plans/gumbel-mcts-arch-sweep-agents-6-silver-thistle.tsv`,
one row per checkpoint (368 rows). A wide companion,
`plans/gumbel-mcts-arch-sweep-agents-6-silver-thistle.wide.tsv`, collapses
each draw's 4 rungs into one row (92 rows). Both generated by
`tools/export_cohort_results.ps1` via the study driver's `export` phase.

## Caveats

- **Not a controlled factorial.** 92 random draws across 11 jointly-varied
  axes (2 of them architecture-specific) cannot isolate any single axis's
  causal effect. The l2, architecture-depth, and rung-peak observations
  above are correlational, reported as data per this project's "report the
  data, do not characterize it" convention, not conclusions.
- **1 seed per draw.** Per-draw Elo sits inside the project's documented
  50-150 Elo seed-noise band; a single draw's rank is not a reliable
  ordering by itself. The mlp-vs-conv architecture gap is population-level
  evidence (46 vs. 46 independent draws), not a per-cell claim -- no
  individual row's exact hyperparameters should be read as "the" optimum.
- **Screening only, not certification.** This is a pinned-fit gauntlet
  against the frozen screening pool. None of these checkpoints are in
  `ranking/roster.txt`; nothing here moves `ranking/CHAMPION.md` (that head
  is `ab(deep=6,...)`, a different search head from `gaz(...)` entirely, so
  this cohort was never eligible to compete for it regardless).
- **Conv's FC head untested.** `--mlp-hidden` (conv's post-flatten FC layer)
  was fixed empty this round; whether adding FC capacity narrows or widens
  the mlp/conv gap is unknown.

## Correctness Gotchas

- **Ledger CSV comma bug**, caught by the Pass-1 2-draw timing check and
  fixed before the full run -- full account in the plan doc. Confirmed fixed
  for the full 368-checkpoint run: zero "no matching standings row" warnings
  in the final export (the timing check had 4/8).
- **REF blocks carry double games.** `ranking/matches_screen_gzarch.jsonl`
  accumulated games from both the Pass-1 timing check and the full run for
  REF_MLP/REF_CONV specifically, because the play phase is not idempotent --
  re-running it replays a checkpoint's full 16-games/opponent gauntlet
  regardless of whether that checkpoint was already screened. Confirmed by
  games count: `games=864` for exactly the 8 REF_MLP/REF_CONV rows,
  `games=432` for all other 360 rows. Not a correctness problem (more games,
  tighter error bars -- `elo_pm` 13 for REF rows vs. 19-20 for the rest --
  same opponents/pool both times), but the REF rows' error bars are not
  directly comparable to the rest of the cohort's, and this is worth fixing
  (make `PlayCohort` skip checkpoints already present in the screening
  store) before the next multi-invocation study of this shape.
- **`Start-Process -PassThru`'s `.ExitCode` gotcha** (documented in Round
  5's plan doc) was already fixed in the template this study copied from;
  no repeat of that failure mode here.

## Future Work

- **Fix `PlayCohort`'s non-idempotency** (ties to the REF-double-games
  gotcha above): make the play phase check the screening store for a
  checkpoint's existing game count before re-submitting its gauntlet, so an
  interrupted-and-resumed run doesn't silently double-count a subset of the
  cohort.
- **Confirm the mlp winner with more seeds** (ties to "Winner" above): a
  single seed's 1023 could itself be inflated by seed noise, same caution as
  Round 5's R87. Re-run M34's exact recipe (mlp hidden=32, sims=500,
  lr=0.01, l2=0, replay=(2000,32), batch=128, open=8) at 2-3 more seeds
  before treating 1023 as a stable number rather than a favorable draw.
- **Sweep conv's FC head** (ties to "Conv's FC head untested" above): a
  follow-up round jointly sweeping `--conv-channels` and `--mlp-hidden`
  together for conv checkpoints, to see whether conv's gap to mlp narrows
  with a comparably-sized post-flatten FC layer instead of a direct linear
  read-out.
- **Isolate architecture depth's effect** (ties to the "architecture depth"
  table): 8-17 draws per cell is too few to separate depth's effect from
  the other 9 jointly-varied axes; a controlled depth-only sweep at fixed
  training/search-shape hyperparameters would isolate it.
- **Certification path for the top mlp checkpoints**: if the developer wants
  to pursue this further, the natural next step is either (a) an unpinned
  certification refit with the top few mlp checkpoints added to
  `ranking/roster.txt` to see if rank #2 holds under a real (non-pinned) fit,
  or (b) the seed-replication study above first, before spending a
  certification refit on what might be a favorable single seed.

## Ideas This Inspired

- The l2=0 pattern has now replicated across two independent rounds (linear
  in Round 5, mlp/conv here) -- worth eventually promoting from "observed
  pattern" to an actual controlled l2 sweep (already flagged as Round 5
  future work, reinforced by this round's replication).
- Given `gaz`+mlp's rank #2 finish is competitive with the pool's best
  `ab(deep=6)` linear agent despite being a completely different search
  algorithm (Gumbel MCTS vs. alpha-beta) and much cheaper per move (mlp
  checkpoints in the top 20 run at roughly 2-25ms/move vs. `ab(deep=6)`'s
  11-450ms/move depending on evaluator), a direct head-to-head study between
  the two search heads at matched wall-clock budget (not matched games)
  could be a more informative comparison than pooled Elo alone.
- This round's architecture gap (mlp beats conv clearly) is the opposite
  shape of theory 27's finding (MLP beat linear on offline loss but LOST
  Elo, under the `tdleaf_self`/alpha-beta regime) -- worth a `Docs/theories.md`
  entry cross-referencing both, since they're answering the same "does
  capacity help" question under two different training/search regimes and
  getting different answers, which is itself informative about where the
  regime-dependence comes from.
