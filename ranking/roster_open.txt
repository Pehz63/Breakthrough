# Diversified-opening roster (2026-07-26). A SECOND, self-contained pool.
#
# Store:   ranking/matches_open.jsonl   (never mixed with ranking/matches.jsonl)
# Outputs: ranking/ratings_open.tsv, standings_open.tsv, games_open.tsv, report_open.md
# Run:     rank.exe play --roster ranking/roster_open.txt --in ranking/matches_open.jsonl \
#                       --out ranking/matches_open.jsonl --games 4 --paired-openings
#          rank.exe rate --roster ranking/roster_open.txt --in ranking/matches_open.jsonl
#
# WHY A SEPARATE POOL. Every agent here wears `.opener(rand,4)`: its first 4 OWN
# half-moves are uniform-random, so a game starts from a random position 8 plies in.
# That only measures strength fairly when BOTH sides randomize. Mixing these agents
# into ranking/roster.txt would pair them against 116 agents that do not, which is
# the asymmetric `--open-side a` condition the opener-bias study showed swings a
# matchup from 65% to 40%. So the diversified agents live here, and their games live
# in their own store.
#
# PAIRED OPENINGS. Run with --paired-openings. The scheduler emits each pair as
# colour-swapped couples, and that flag gives both games of a couple ONE seed derived
# from the canonically ordered pair. The random opener draws from rand() and no brain
# is consulted during the opener window, so an identical rand() stream yields an
# identical opening line. The couple therefore plays the SAME position with colours
# reversed. Agents are compared on how they recover from equal ground, not on which
# of them drew the kinder start. Without this flag the pool still works but carries
# opening luck as pure variance.
#
# NO BOOK AGENTS. A book is keyed on exact position hashes, so after a random opening
# it never fires and a book agent is identical to its bare core (theory 38). Books are
# a fixed-start phenomenon and stay in the main pool, which is where they mean
# something. See todo.md for the open question of whether a book could instead be
# mined to RECOVER from bad random openings.
#
# SELECTION. One strongest representative per evaluator family, plus the scale.
# Elo values in comments are from the 2026-07-26 main-pool fit and are there only to
# say why each agent was picked. They are NOT comparable to anything this pool
# produces: different instrument, different fit.

anchor  rand@1                                                  # already plays randomly, needs no opener

# --- Learned value models, replay/selfplay recipe, strongest per lineage ---
# All v2 sparse piece-square LINEAR value heads. Distinct recipe from the dist
# models below: these learn from game outcomes, the dist models from designed
# mu/sigma labels (data/labels/, see ML.md).

on      ab(d6,tt,ord,nb200k)@1.learned(s3,68364898,value,lin,129-1,con100)@1.opener(rand,4)@1     # 1063, replay-trained lineage
on      ab(d6,tt,ord,nb200k)@1.learned(s98,5801570e,value,lin,129-1,con100)@1.opener(rand,4)@1    # 1040, the deposed champion's core

# --- Distributional (dist) models: position-oracle recipe, mu/sigma heads ---
# NOTE s76 is a DIST model (type=dist, mu_type=linear, no hidden layer), not one of
# the replay-trained linear models above. It was mis-grouped with them when this
# roster was first written. Search reads only the mu head, so in play it is a linear
# evaluator, but its training recipe and data are the dist pipeline's.
# The rest of this family, and the architecture ladder that separates width from
# seed, is at the bottom of this file.
on      ab(d6,tt,ord,nb200k)@1.learned(s76,ef183148,dist,lin,129-1,sig129-1,con100)@1.opener(rand,4)@1    # linear mu. 1077 fixed-start, and 1235 = TOP of its head in THIS pool

# --- Dist-model architecture ladder (added 2026-07-26) -----------------------
# Question: why does learned(s111,...) rate LAST among the d6 contenders here
# (1125 +/- 20) and score only 25% against the chip counter, when it outrated that
# same chip counter in the fixed-start pool?
#
# s111 is the NNUE-shaped head from theory 37: mu_layers = 129,512,8,1. A 512-wide
# first layer feeding an 8-unit BOTTLENECK. Two candidate explanations, and the pool
# already hints at the answer: learned(s76,...) is ALSO a dist model (mu_type=linear,
# no hidden layer) and it is TOP of that head at 1235. So "dist models generalise
# badly" is already doubtful, and the suspicion falls on the 8-unit bottleneck.
#
# This ladder separates architecture from seed. All six models below were trained by
# the same recipe on the same labelstore (data/labels/raw_train.jsonl), so the only
# differences are mu width/depth and the training seed.
#
#   mu_layers          slots (seed)                     already in pool
#   linear (no hidden) s76 (1001)                       YES, rates 1235 (top)
#   129,128,64,1       s77 (1001), s78 (2002)           no  <- added here
#   129,256,128,1      s79 (3003)                       no  <- added here
#   129,512,8,1        s110 (1001), s111 (2002),        s111 only, rates 1125
#                      s113 (4004), s115 (6006)             <- 3 more added here
#
# Reading the result: if all four NNUE-shaped seeds sit at the bottom, it is the
# ARCHITECTURE (the bottleneck). If s111 is alone down there, it is SEED NOISE and
# theory 8's 50-150 Elo band covers it. If the standard and wide MLPs also sag while
# the linear mu stays on top, the cost is having ANY hidden layer, not the shape.
#
# Note on the overfitting hypothesis: theory 37 measured held-out prediction for this
# architecture as NEUTRAL (MAE 143.5 / NLL 0.40795 vs the wide head's 146.2 / 0.4079),
# so it is not overfit to the training SAMPLE. But those held-out positions came from
# posgen sampling standard-start games, i.e. the same DISTRIBUTION. Distribution-level
# overfit is exactly what this pool tests and what that held-out number cannot see.

on      ab(d6,tt,ord,nb200k)@1.learned(s77,ddaa5090,dist,mlp,129-128-64-1,sig129-32-1,con100)@1.opener(rand,4)@1    # 129,128,64,1  seed 1001
on      ab(d6,tt,ord,nb200k)@1.learned(s78,2fa21eda,dist,mlp,129-128-64-1,sig129-32-1,con100)@1.opener(rand,4)@1    # 129,128,64,1  seed 2002 (seed replicate)
on      ab(d6,tt,ord,nb200k)@1.learned(s79,18f19059,dist,mlp,129-256-128-1,sig129-64-1,con100)@1.opener(rand,4)@1    # 129,256,128,1 seed 3003 (wide)
on      ab(d6,tt,ord,nb200k)@1.learned(s110,1466db6c,dist,mlp,129-512-8-1,sig129-64-1,con100)@1.opener(rand,4)@1   # 129,512,8,1   seed 1001
on      ab(d6,tt,ord,nb200k)@1.learned(s113,e3cc8b4e,dist,mlp,129-512-8-1,sig129-64-1,con100)@1.opener(rand,4)@1   # 129,512,8,1   seed 4004
on      ab(d6,tt,ord,nb200k)@1.learned(s115,21d7e638,dist,mlp,129-512-8-1,sig129-64-1,con100)@1.opener(rand,4)@1   # 129,512,8,1   seed 6006
