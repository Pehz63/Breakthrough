# Default gauntlet pool for rating a new/candidate agent during training or
# screening (rank.exe gauntlet --pool this file, or equivalent). Not the full
# roster and not a study-scratch file -- a standing, git-tracked reference
# pool, analogous to roster_top.txt (openless top-of-table boosting) but built
# for the opposite job: giving ANY new agent, at ANY strength, a fixed set of
# opponents spanning the standings from top to near-bottom, across all 5
# opener categories, so a screening gauntlet's Elo lands on an interpretable
# point of the existing scale instead of only being measurable near the top.
#
# Built 2026-08-17 for the Gumbel-Zero cvisit/cscale/m joint-sweep study
# (plans/gumbel-mcts-*), then adopted as the project default. Head throughout:
# ab(deep=6,tt,ord,nodes=200k)@1. Elo quoted in comments is from the
# 2026-08-17 ranking/standings.tsv fit -- re-check the current standings.tsv
# before treating these numbers as current (never compare absolute Elo across
# fits, see CLAUDE.md's ranking hygiene rules).
#
# Composition:
#  - Top of each of the 5 opener categories (openless/4-book/8-book/4-random/
#    8-random), one pick per distinct evaluator regime present near the top
#    of that category (tdleaf_self, position_elo, pool_games, weight_merge),
#    plus that category's chip-counter control -- weaker same-regime
#    duplicates excluded.
#  - A spread of weaker opponents (800s down to ~100 Elo) so the pool isn't
#    all clustered at 900+: a few more regime-diverse learned() models in the
#    800s and mid-range, then the chip-counter's own dilution ladder
#    (dil(prob=N)) for a clean, single-regime path down to a near-floor
#    opponent.
#
# To extend: keep the regime-diversity + Elo-spread principle above, re-derive
# picks from a freshly regenerated ranking/standings.tsv (not this file's
# stale comments), and update the Elo comments below to the new fit's date.
